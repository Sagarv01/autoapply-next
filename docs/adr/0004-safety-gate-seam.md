# ADR-0004: Where the safety gate intercepts the engine

Date: 2026-05-29
Status: Proposed (until verified by integration testing)

## Context

The engine submits a real application from exactly one place: `seek_apply._submit`, a single function at `vendor/job-finder/seek_apply.py` line 2061, called once per application from `apply_seek_quick` at line 256 via `await _submit(page)`. That call site uses a bare-name lookup, resolved at call time against `seek_apply`'s module globals, which means reassigning `seek_apply._submit = <gated_version>` takes effect for every subsequent call without touching the engine source (the non-negotiable from ADR-0001). The user's framing is exact: "this gate is the only thing preventing real applications going to real employers under my real name," so the seam has to be small, auditable, and impossible to miss when reading the wrapper. Four alternatives were weighed. (1) Fork the engine and add a kwarg, rejected because it violates the unmodified-engine rule. (2) Patch the click selectors to invalid CSS so the engine cannot find the button, rejected because the engine raises `SeekApplyError` on missing selectors which is indistinguishable from a real form-fill failure and would poison the test signal. (3) Wrap the entire `applicator.apply` in a fake that returns early, rejected because it would skip the form-fill steps which are exactly what we want to verify in dry-run. (4) Patch `_submit` only, chosen because it intercepts the one operation we want to prevent while leaving every preceding step (resume upload, field fill, validation) running against real Seek.

## Decision

Install a process-global monkey-patch on `seek_apply._submit` via a context manager. In dry-run mode the gated `_submit` mirrors the engine's pre-submit hygiene (ticks the terms checkbox), locates the submit button using the same four selectors the engine uses, asserts the button is both visible and enabled, captures a full-page screenshot to the run's artefact directory, then raises a typed `DryRunReached` exception that the adapter catches and converts to a `result=dry_run_ok` outcome. This proves the form was filled to submission-ready without filing an application. In real-submit mode the gated `_submit` delegates to the captured original; the patch is idempotent and the context manager restores the original on exit. The worker singleton from ADR-0003 enforces "one gate active at a time" because the patch lives in module globals. A contract test, `test_gate_selectors_match_engine`, reads the engine source and asserts every selector in the gate's `_SUBMIT_SELECTORS` list appears verbatim in `seek_apply.py`; the test fails loudly if the engine adds a new selector or renames `_submit`, which is the desired drift detection rather than a silent miss.

## Consequences

The seam is one function, one assignment, and one contract test, which the user (or any reviewer) can read in under five minutes and convince themselves of. `ALLOW_REAL_SUBMIT` defaults `False` in the adapter, in the Settings screen, in the test suite, and in the CI workflow; no path in the codebase sets it to `True` except the user toggling Settings in the GUI. The dry-run artefact (terms ticked, button-state assertion, full-page screenshot) is strong enough evidence of submit-readiness to gate the Phase 2 to Phase 3 transition. The drift risk is real (the gate's selector list is a copy of the engine's inline list) but is caught by the contract test on the next run rather than at production submission time. If the engine ever moves to a different submit function or removes `_submit`, the import fails fast at adapter load time, which is the desired behaviour: no application can be filed while the gate is misconfigured.
